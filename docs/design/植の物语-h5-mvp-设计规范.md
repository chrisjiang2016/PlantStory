# 植の物语 H5 MVP 设计规范

> 版本：v0.1
> 
> 规范类型：视觉与交互基线
> 
> 适用范围：`prototype/h5-app/public/` 当前 H5 MVP，以及后续 Flutter Web / 移动端页面还原
> 
> 基准来源：H5 MVP 首页、拍照识别、植物详情、养护提醒、病虫害诊断、植物百科和个人中心页面
> 
> 建立日期：2026-08-12

---

## 1. 设计定位

### 1.1 产品气质

植の物语是一款面向植物新手和日常养护用户的植物管理工具。界面应传达以下感受：

- **自然**：以叶片绿、浅色背景和植物相关图形建立品类识别。
- **轻松**：使用柔和渐变、较大圆角和低对比阴影，降低工具感和学习成本。
- **陪伴**：文案采用“早安”“今日任务”“先去拍照识别一盆植物”等温和、鼓励式表达。
- **可执行**：每个页面围绕一个主要任务组织内容，例如识别、完成提醒、查看百科或开始养护。

### 1.2 视觉关键词

`自然绿色`、`浅色留白`、`柔和卡片`、`轻量渐变`、`圆润移动端容器`、`低压力反馈`。

### 1.3 风格边界

- 不使用高饱和、荧光感或大面积深色背景作为默认主题。
- 不使用复杂纹理、装饰性大图或与任务无关的动效。
- Emoji 目前是 H5 MVP 的快速原型表达；正式 Flutter/Web 版本应逐步替换为统一 SVG 图标集，保证风格、可访问性和跨平台一致性。
- 渐变只用于页面背景、品牌头部和重点视觉容器，不用于所有按钮或所有卡片。

## 2. 设计基础变量

后续实现应优先使用语义化 Token，避免在组件中直接散落颜色值。

### 2.1 颜色 Token

| Token | 色值 | 用途 |
|---|---|---|
| `color.brand.primary` | `#2E7D32` | 主文字、主按钮、当前导航、关键链接 |
| `color.brand.primary-dark` | `#1B5E20` | 主按钮 Hover / Pressed、深色强调 |
| `color.brand.green` | `#66BB6A` | 主渐变起点、进度、成功状态 |
| `color.brand.green-light` | `#81C784` | 主渐变终点、次级绿色背景 |

| `color.surface.card` | `#FFFFFF` | 卡片、弹窗、底部导航 |
| `color.surface.green-tint` | `#E8F5E9` | 淡绿色标签、插图底、辅助背景 |

| `color.surface.mint` | `#F1F8F4` | 识别结果或轻量状态背景 |

| `color.status.warning-bg` | `#FFF9E6` | 风险或提醒背景 |

### 2.2 推荐渐变

```css
--gradient-brand: linear-gradient(135deg, #66BB6A 0%, #81C784 100%);
--gradient-page: linear-gradient(135deg, #E8F5E9 0%, #FFF9E6 100%);
--gradient-tint: linear-gradient(135deg, #E8F5E9 0%, #FFF9E6 100%);
```

使用规则：

- `gradient-brand` 用于首页头部、页面主头部、主 CTA。
- `gradient-page` 用于页面外部背景或插图区域。
- 文字不能直接叠加在浅色渐变上，必须保证对比度；品牌头部中的文字使用白色并保留足够透明度层级。

### 2.3 透明度

| 用途 | 推荐值 |
|---|---:|
| 头部辅助文字 | `0.90` |
| 头部半透明按钮 | `rgba(255, 255, 255, 0.20)` |
| 白色浮层 | `rgba(255, 255, 255, 0.92)` |
| 遮罩 | `rgba(0, 0, 0, 0.50)` |
| 绿色状态阴影 | `rgba(102, 187, 106, 0.15–0.30)` |

## 3. 字体与排版

### 3.1 字体栈

```css
font-family: 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
```

正式产品中应保持系统字体优先，避免因网络字体加载造成文字闪烁或布局跳动。

### 3.2 字号层级

| Token | 字号 | 行高 | 用途 |
|---|---:|---:|---|
| `type.display` | `24px` | `1.35` | 首页问候、重要页面标题 |
| `type.title` | `20px` | `1.4` | 页面主标题、识别页标题 |
| `type.section` | `18px` | `1.45` | 区块标题、植物名称 |
| `type.body-lg` | `16px` | `1.5` | 卡片标题、主要正文 |
| `type.body` | `14px` | `1.55` | 默认正文、按钮文字 |
| `type.caption` | `13px` | `1.5` | 辅助说明、状态文案 |
| `type.meta` | `12px` | `1.45` | 时间、分类、细节 |
| `type.label` | `11px` | `1.4` | 标签、底部导航辅助文字 |

使用规则：

- 页面正文默认不小于 `14px`；移动端主要阅读内容优先使用 `16px`。
- 标题使用较低字重，延续 H5 的柔和感；不要大量使用全粗体。
- 每个页面只保留一个 `display/title` 级主标题，其余通过区块标题和间距建立层级。
- 中文正文行高不低于 `1.45`，避免卡片内文字拥挤。
- 长文本允许换行，不以强制省略破坏任务说明。

### 3.3 文案语气

- 使用简短、明确、带陪伴感的句子。
- 操作按钮优先使用动词：`立即开始`、`去识别`、`完成养护`、`查看详情`。
- 错误提示说明“发生了什么”和“下一步做什么”，避免只展示技术错误码。
- 空状态应包含图形、当前状态、下一步建议，不能只展示“暂无数据”。

## 4. 布局与响应式

### 4.1 H5 画布

当前 H5 MVP 使用居中的移动端设备模拟容器：

- 设计基准宽度：`375px`。
- 内容容器最大宽度：`448px`，桌面浏览器居中展示。
- 外层页面使用淡色渐变背景，设备容器使用 `#FAFAFA`。
- 设备容器圆角：`40px`。
- 设备容器阴影：`0 20px 60px rgba(0, 0, 0, 0.15)`。

正式页面应使用响应式布局：

| 断点 | 规则 |
|---|---|
| `0–767px` | 移动端单列布局，内容宽度占满，保留 `16px` 页面边距 |
| `768–1023px` | 平板布局，主内容最大宽度 `640px`，可保留设备式阅读宽度 |
| `1024px+` | 桌面预览居中，内容最大宽度 `448px` 或按业务页面扩展；不拉伸移动端卡片比例 |

### 4.2 间距系统

使用 4px 基础间距，优先使用以下档位：

| Token | 间距 | 典型用途 |
|---|---:|---|
| `space-1` | `4px` | 图标与文字微间距 |
| `space-2` | `8px` | 标签内间距、紧凑列表 |
| `space-3` | `12px` | 卡片内部元素 |
| `space-4` | `16px` | 页面边距、常规组件间距 |
| `space-5` | `20px` | 卡片内边距、区块间距 |
| `space-6` | `24px` | 区块标题与内容 |
| `space-8` | `32px` | 页面级分组间距 |
| `space-10` | `40px` | 头部或大型空状态留白 |

### 4.3 页面结构

推荐页面骨架：

```text
页面背景
└── 移动端内容容器
    ├── 顶部头部 / 返回栏
    ├── 主内容滚动区
    └── 固定底部导航（需要时）
```

规则：

- 固定底部导航存在时，主内容底部至少预留 `88px`，避免最后一项被遮挡。
- 页面不使用横向滚动作为主要交互。
- 不在一个页面内嵌套多个独立滚动区域，优先保留一个主滚动容器。
- 顶部返回操作保持位置稳定，返回按钮触控区域不小于 `44 × 44px`。

## 5. 圆角、阴影与层级

### 5.1 圆角 Token

| Token | 值 | 用途 |
|---|---:|---|
| `radius-sm` | `10px` | 输入框、紧凑按钮、标签 |
| `radius-md` | `12px` | 状态块、图片占位、次级按钮 |
| `radius-lg` | `15px` | 主要卡片、内容分组 |
| `radius-xl` | `20px` | 快捷入口容器、主操作卡片 |
| `radius-pill` | `999px` | 胶囊标签、返回按钮、状态徽章 |
| `radius-device` | `40px` | H5 设备容器 |

### 5.2 阴影 Token

```css
--shadow-card: 0 2px 10px rgba(0, 0, 0, 0.05);
--shadow-soft: 0 4px 20px rgba(0, 0, 0, 0.08);
--shadow-brand: 0 6px 25px rgba(102, 187, 106, 0.15);
--shadow-brand-strong: 0 6px 20px rgba(102, 187, 106, 0.30);
--shadow-device: 0 20px 60px rgba(0, 0, 0, 0.15);
--shadow-modal: 0 10px 40px rgba(0, 0, 0, 0.30);
```

使用规则：

- 卡片只使用一层柔和阴影，不同时叠加多组阴影。
- 主操作可使用品牌色阴影，普通内容卡片使用 `shadow-card` 或 `shadow-soft`。
- 阴影用于表达层级，不用于装饰每一个区块。

## 6. 核心组件规范

### 6.1 顶部头部

- 背景：`gradient-brand`。
- 标题：白色，`20–24px`，字重 400–500。
- 辅助文字：白色，透明度约 `0.90`，`13–14px`。
- 首页可使用问候语和任务数量；功能页优先使用返回按钮 + 页面标题。
- 返回按钮使用半透明白色胶囊，视觉高度约 `36px`，实际触控区域至少 `44px`。

### 6.2 快捷入口

- 3 个入口一行，移动端等宽排列。
- 背景使用 `color.surface.green-tint` 与 `color.surface.warm-tint` 的轻量组合。
- 图形置于上方，文字置于下方，文字使用 `13–14px`。
- 入口之间保留至少 `8px` 间距。
- 入口是整块可点击区域，不只让图标可点击。

### 6.3 内容卡片

- 背景：`#FFFFFF`。
- 圆角：默认 `15px`，强调型卡片可使用 `20px`。
- 内边距：默认 `16–20px`。
- 标题使用 `16–18px`，正文使用 `13–14px`，辅助说明使用 `12–13px`。
- 卡片内图形或图片使用固定尺寸或 `aspect-ratio`，避免异步加载造成布局跳动。
- 空状态卡片必须包含行动入口。

### 6.4 主按钮

- 背景：`color.brand.primary` 或 `gradient-brand`。
- 文字：白色，`14px`。
- 圆角：`10–12px`。
- 最小高度：`44px`；重要 CTA 建议 `48px`。
- 按压态：切换为 `color.brand.primary-dark` 或降低亮度。
- 异步操作时必须禁用重复点击并显示加载状态。

### 6.5 次按钮

- 背景：`#F5F5F5` 或透明。
- 文字：`color.text.body` 或 `color.brand.primary`。
- 边框：必要时使用 `1px solid #E0E0E0`。
- 不应与主按钮使用同等视觉权重。

### 6.6 标签与状态徽章

- 使用胶囊形状，圆角 `10–12px` 或 `999px`。
- 常规状态：`#E8F5E9` + `#2E7D32`。
- 注意状态：`#FFF9E6` + `#F57C00`，同时配合文字或图标，不只依赖颜色。
- 字号 `11–12px`，内边距建议 `4px 8px`。

### 6.7 输入框

- 高度建议 `44–48px`。
- 默认边框：`1px solid #E0E0E0`。
- 聚焦边框：`#66BB6A`，同时提供明显焦点状态。
- 圆角：`10px`。
- 必须有可见字段标签；placeholder 只能作为补充说明。
- 错误文案显示在对应输入框附近，颜色之外同时使用图标或文字说明。

### 6.8 底部导航

- 最多 5 个一级入口，当前 H5 使用：首页、识别、诊断、百科、我的。
- 固定在内容容器底部，背景白色，上边框 `1px solid #F0F0F0`。
- 图标位于文字上方，图标约 `24px`，标签 `11px`。
- 当前项使用 `#2E7D32`，未选中项使用 `#9E9E9E`。
- 每项实际点击区域至少 `44 × 44px`。
- 导航入口名称和图标语义必须一致，不使用仅颜色区分当前状态。

### 6.9 模态框与处理中状态

- 使用半透明黑色遮罩，背景内容不可操作。
- 模态卡片背景使用白色，圆角 `20px`，阴影使用 `shadow-modal`。
- 图片识别等超过 1 秒的操作必须提供处理中反馈。
- 处理中状态应说明当前阶段，例如“正在识别植物”“正在整理养护建议”，避免只显示旋转图标。
- 必须提供取消或返回路径，除非操作不可取消且持续时间很短。

## 7. 页面级规范

### 7.1 首页

信息优先级：问候与今日任务 → 快捷入口 → 我的植物 → 最近识别 → 底部导航。

- 首页头部承担品牌和状态展示，不放过多操作。
- “我的植物”为空时，必须展示“立即开始”入口。
- “最近识别”为空时，展示上传照片的下一步建议。
- 首页首屏优先展示用户今天能执行的操作，不优先展示长说明。

### 7.2 拍照识别

- 首要任务是上传或拍摄植物照片。
- 图片上传区域使用淡绿色渐变、虚线边框和中心图形建立可操作暗示。
- 上传后展示图片预览、识别状态和结果，不在结果页同时堆叠过多次要信息。
- “加入我的植物”属于识别结果页的主要 CTA；“查看详情”“重新识别”为次级操作。
- 识别失败必须提供重新上传、重试或手动搜索路径。

### 7.3 植物详情

- 顶部优先展示植物名称、识别状态和主视觉。
- 养护信息使用分组卡片呈现，如光照、浇水、温度和难度。
- 属性值应使用文字 + 图形 / 标签表达，不只使用颜色或进度条。
- 详情页主操作应围绕“开始养护”或“加入我的植物”保持单一。

### 7.4 养护提醒

- 头部清楚展示当天待办数量。
- 任务列表优先显示植物名称、任务类型、时间和完成操作。
- 完成操作要有即时视觉反馈，并从待办列表移动到已完成状态。
- 无任务时展示轻量空状态和建立提醒的入口，不显示空白页面。

### 7.5 诊断与百科

- 诊断页强调症状描述、照片和下一步建议；不把不确定结果表达成确定诊断。
- 百科页强调搜索、筛选和详情；筛选条件应可清除，空结果需要解释。
- 医疗或病害类结果使用“可能”“建议观察”等谨慎措辞，并提供人工确认或进一步查看入口。

## 8. 交互状态规范

所有可交互组件至少定义以下状态：

| 状态 | 视觉要求 |
|---|---|
| Default | 使用默认 Token |
| Hover | 桌面端轻微变深或出现品牌阴影，不改变布局尺寸 |
| Pressed | 主色加深，或增加轻量缩放 / 状态层 |
| Focused | 显示 `2–4px` 可见焦点环，键盘可识别 |
| Disabled | 降低对比度，禁止点击，并保留原因说明 |
| Loading | 显示进度反馈，避免按钮文字突然消失造成布局跳动 |
| Success | 使用绿色状态表达，并配合文字或图标 |
| Warning / Error | 使用橙色 / 红色语义，同时提供文本说明 |
| Empty | 图形 + 状态说明 + 下一步 CTA |

动效规则：

- 常规过渡：`150–200ms`。
- 页面或卡片进入：`200–300ms`。
- 动效服务于状态变化，不使用纯装饰性持续动画。
- 支持 `prefers-reduced-motion`，用户要求减少动效时关闭非必要过渡。

## 9. 图标与插图规范

### 当前 H5 MVP

- 使用 Emoji 快速表达拍照、提醒、百科、诊断等入口。
- Emoji 仅作为原型占位，不作为正式跨平台视觉资产。

### 后续正式实现

- 统一使用 Lucide、Material Symbols 或项目选定的单一 SVG 图标库。
- 图标线宽、圆角、视觉尺寸保持一致。
- 图标按钮必须有 `aria-label` 或 Flutter `Semantics` 标签。
- 重要图片提供描述性替代文本；纯装饰图使用空替代文本。
- 植物图片使用真实内容优先，避免使用无法识别主体的模糊或纯氛围图。

## 10. 可访问性与质量门槛

后续页面验收至少满足：

- 普通文本对比度达到 WCAG AA，目标为 `4.5:1` 以上。
- 所有主要按钮和导航项触控区域不小于 `44 × 44px`。
- 页面可通过键盘访问，焦点顺序与视觉顺序一致。
- 不只使用颜色传递成功、警告、错误和选中状态。
- 页面支持系统字体放大，文字增大时不遮挡、不溢出关键操作。
- 图片、图标、表单控件具备可访问名称。
- 主要内容不被固定底部导航遮挡。
- 移动端不出现横向滚动。
- 异步内容预留尺寸，避免加载导致布局跳动。
- 网络失败、空数据、权限不足和重复提交均有明确反馈。

## 11. 前端实现约束

### H5 / HTML/CSS

- 后续新增页面不得重复复制整段颜色和间距值，优先抽取 `:root` CSS Variables。
- 公共头部、底部导航、卡片、按钮和状态标签应逐步抽取为共享样式或模板片段。
- 页面必须包含 `viewport` 配置，不能禁用用户缩放。
- 图片声明尺寸或使用 `aspect-ratio`，非首屏图片使用懒加载。

### Flutter

- 颜色、字号、圆角和间距映射到 `ThemeData` / `ColorScheme` / 自定义 Design Tokens。
- 组件优先使用 Flutter 原生可访问控件，不以纯 `GestureDetector` 替代按钮。
- 使用 `Semantics` 为图标、状态和图片补充语义。
- Web 与原生端保持同一套 Token，允许根据平台调整导航和安全区，但不随意改变品牌视觉。

### 代码评审检查

- 是否使用语义化 Token，而不是新增孤立的十六进制颜色？
- 是否保留了单一主要 CTA？
- 是否处理 loading、empty、error、disabled 和 focused 状态？
- 是否存在小于 `44px` 的主要触控目标？
- 是否在移动端验证了长文案、系统字体放大和底部导航遮挡？
- 是否引入了与当前风格不一致的图标、阴影、圆角或渐变？

## 12. 当前规范与 H5 实现的差异记录

以下内容是从 H5 MVP 现状提炼后，明确作为后续改进项保留的约束：

1. H5 当前页面存在较多页面内联 CSS；后续应抽取统一 Token 和共享组件。
2. H5 当前主要使用 Emoji；正式客户端应替换为统一 SVG 图标。
3. H5 部分辅助文字使用 `11–13px`；正式客户端需避免将该字号用于长文本或关键操作说明。
4. H5 当前以 `375px` 设备容器为主要展示方式；正式 Web 页面需补齐平板、桌面和不同手机宽度适配。
5. H5 当前主要是 localStorage / 原型状态；本规范只定义视觉和交互表现，不代表数据链路已经接入正式 Nest API。

## 13. 版本与变更规则

- 新增颜色、字号、圆角或阴影前，先确认现有 Token 是否可复用。
- 修改品牌主色、页面背景、底部导航结构或主要 CTA 样式时，必须同步更新本规范和相关页面。
- 新增页面应标注所属用户任务、主要 CTA、空状态、错误状态和返回路径。
- 视觉变更至少在移动端 `375px`、`390px` 和桌面浏览器预览一次。
- 以实际页面截图、交互验证和可访问性检查作为验收证据，不只以代码存在作为完成依据。
