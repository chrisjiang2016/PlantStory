## 二、问题诊断与解决（13:11 - 14:50）

### 问题根源
Railway 后端的 PostgreSQL 数据库表结构未初始化，导致注册接口尝试写入数据时失败。

### 解决方案
生成并提交 Prisma 迁移文件，让 Railway 的 `prisma migrate deploy` 自动创建表结构。

### 关键步骤

1. **确认 Railway 环境**
   - 项目：resilient-quietude
   - 服务：PlantStory
   - 数据库：Postgres（已存在）
   - Root Directory：`/backend`

2. **配置环境变量**
   - `DATABASE_URL`：从 Postgres 服务复制
   - `JWT_SECRET`：`plant-story-jwt-secret-2026`
   - `JWT_REFRESH_SECRET`：`plant-story-refresh-secret-2026`

3. **生成 Prisma 迁移文件**
   ```bash
   cd plant-story/backend
   npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > prisma/migrations/0_init/migration.sql
   ```

4. **创建 migration_lock.toml（TOML 格式）**
   ```toml
   provider = "postgresql"
   ```

5. **提交并推送**
   ```bash
   git add backend/prisma/migrations/
   git commit -m "fix: add Prisma migration files for Railway deployment"
   git push origin main
   ```

## 三、遇到的关键技术坑

### 1. migration_lock.toml 格式错误
- ❌ 写成了 JSON 格式
- ✅ 必须是 TOML 格式：`provider = "postgresql"`

### 2. Railway Root Directory 导致配置文件位置错误
- Root Directory 是 `/backend`，配置文件要放在 `backend/railway.toml`

### 3. 构建阶段没有环境变量
- 构建阶段（Build）无法访问 `DATABASE_URL`
- 数据库操作只能在运行阶段（Deploy）执行

### 4. Railway 自动检测优先级高
- Railway 自动检测 Prisma 并运行 `migrate deploy`
- 顺应平台机制比对抗它更有效
