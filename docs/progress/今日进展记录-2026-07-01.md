### 2. Perenual API 植物详情

今天中途曾遇到问题：
- 本地代理调用持续返回 404
- 一度误判为 key 或 endpoint 问题

后续排查过程：
1. 核对 swagger 文档：
   - `https://perenual.com/swagger/perenual_openapi_v3.yaml`
2. 确认官方路径正确：
   - `https://perenual.com/api/v2/species-list`
   - `https://perenual.com/api/v2/species/details/{id}`
3. 做最小真实调用验证：
   - 官方直连返回 200
4. 最终定位根因：
   - `dotenv` 默认不会覆盖进程里已有的旧环境变量
   - Node 实际读取到的是旧的脱敏 key
5. 修复方案：
   - `dotenv.config({ path: envPath, override: true })`

修复后结果：
- 本地代理 `/api/plant-detail?name=Epipremnum aureum` 返回 200
- 已成功拿到真实植物数据

结论：
- **Perenual API 可用** ✅

## 七、今天解决掉的关键问题

### 1. Perenual 本地代理一直 404
最终根因：
- 不是接口地址错
- 不是 key 无效
- 是 Node 进程实际读到旧环境变量

### 2. H5 页面返回路径错误
最终根因：
- `pages` 子目录页面使用相对路径 `index.html`
- 导致跳错目录

### 3. 从原型到可运行 H5 的状态断层
解决方式：
- 抽离 `app.js`
- 统一 API 调用与 localStorage 状态
- 让多个页面共享同一套运行数据
