### Sprint B：补齐后端 V1（预计 7-10 天）

**目标：V1 后端功能完整、所有核心 API 有测试覆盖。**

#### B1：实现 Diagnosis 模块（4h）

- 创建 `diagnosis/` Module / Controller / Service / DTO
- `GET /api/v1/diagnosis/diseases`：病虫害知识库查询（关键词、类型、分页）
- `GET /api/v1/diagnosis/diseases/:id`：病虫害知识详情
- `POST /api/v1/diagnosis`：保存用户确认后的排查记录（症状描述、可选图片链接、可选知识条目）
- `GET /api/v1/diagnosis/history`：当前用户的排查历史
- `GET /api/v1/diagnosis/:id`：当前用户的单条排查记录

**验收**：Swagger 可见 5 个接口；覆盖知识库查询、记录创建/历史/详情、跨用户隔离和参数校验。自动图像诊断、文件上传与诊断收藏不属于当前 V1。

#### B2：实现 Encyclopedia 模块（3h）

- 创建 `encyclopedia/` Module / Controller / Service / DTO
- `GET /api/v1/encyclopedia`：搜索/筛选/分页（支持按场景/难度/类型筛选，PRD §5.5）
- `GET /api/v1/encyclopedia/:id`：植物详情（从 PlantSpecies 表读取，Perenual API 兜底）

**验收**：Swagger 可见 2 个接口，单测覆盖搜索与详情。

#### B3：补 Recognition 回归测试（2h）

- 模拟上传图片（mock 百度 AI 响应）+ 植物识别接口返回
- 识别失败时的错误响应
- 识别结果一键添加到"我的植物"

**验收**：3 个用例通过。

#### B4：补 Reminders 回归测试（3h）

- 创建提醒、按植物查询提醒、完成打卡并由服务端生成下一次重复提醒、编辑、删除。
- 当前不为延期/跳过编写“已实现”测试；这两项需在专用接口与审计字段落地后单独实现。

**验收**：覆盖创建、查询、完成重复提醒、编辑、删除及用户隔离的核心用例通过。

#### B5：补 CareLogs / Diaries / Favorites / Achievements 测试（5h）

- 每个模块 2-3 个核心用例（创建、查询、删除 / 收藏切换 / 成就进度更新）

**验收**：6 个模块共 12-15 个用例通过。

#### B6：实现统一错误响应过滤器（2h）

- `HttpExceptionFilter`：标准化 `{ code, message, timestamp, path }` 格式
- 全局注册 `APP_FILTER`

**验收**：任意接口错误返回一致格式，单测验证。

#### B7：Recognition 接口防护（3h）

- 速率限制：单用户 10 次/分钟（`@nestjs/throttler`）
- 请求缓存：相同图片 hash 5 分钟内不重复调外部 API
- Perenual API 调用添加超时（5s）+ 重试（1 次）

**验收**：压测验证限流生效，缓存命中日志可见。

**Sprint B 里程碑（M2）**：Diagnosis + Encyclopedia 可用，全部 10 个模块 45+ 接口，后端单测/集成测试 ≥ 80% 核心路径覆盖，`npm test` 全部通过。

## 四、上线流程

### 4.1 Web 端上线（最快）

Web 端部署链最短，M8 完成后 1 天内可上线。

| 步骤 | 内容 | 耗时 |
|---|---|---|
| 1 | 购买域名（如 plantstory.app） | 即时 |
| 2 | 云服务器（建议 2C4G 起步） | 即时 |
| 3 | Docker Compose 部署全栈服务 | 1h |
| 4 | Nginx 反向代理 + Let's Encrypt HTTPS | 1h |
| 5 | DNS 解析到服务器 IP | 即时~数小时生效 |
| 6 | 生产环境 `.env` 配置（PostgreSQL 密码、COS AK/SK、百度 AI Key、Perenual Key） | 1h |

### 4.2 App Store（iOS）上线

| 步骤 | 内容 | 耗时 |
|---|---|---|
| 1 | Apple Developer 账号注册 | $99/年，审核 1-3 天 |
| 2 | Xcode 中配置 Bundle ID、签名证书、Provisioning Profile | 1h |
| 3 | 准备 App Store Connect 元数据：名称、副标题、描述、截图（6.7"/6.1"）、关键词 | 3h |
| 4 | 准备隐私标签（Privacy Nutrition Label）和隐私政策 URL | 1h |
| 5 | Archive → 上传到 App Store Connect → 提交审核 | 30min |
| 6 | 审核 | 通常 1-3 天，首次可能延长 |

**常见被拒原因**：缺少隐私政策、权限描述不清（NSPhotoLibraryUsageDescription / NSCameraUsageDescription）、APP 图标与截图不一致。

### 4.3 Google Play（Android）上线

| 步骤 | 内容 | 耗时 |
|---|---|---|
| 1 | Google Play 开发者账号注册 | 一次性 $25，审核 1-2 天 |
| 2 | 创建应用，填写描述、截图、分类（生活方式/工具） | 2h |
| 3 | 生成签名 KeyStore，配置 Gradle 签名 | 1h |
| 4 | 隐私政策链接 + 数据安全声明 | 1h |
| 5 | 上传 aab → 提交审核 | 30min |
| 6 | 审核 | 一般 1-2 天 |

## 六、技术架构对齐

PRD 中记录的技术栈与当前实际实现有出入，以下为最终确认版本：

| 层次 | PRD 原记录 | 实际落地 | 说明 |
|---|---|---|---|
| 后端框架 | Node.js + Express | NestJS 11 | 已落地，类型安全 + 依赖注入优势 |
| ORM | MongoDB | Prisma 7.8 + PostgreSQL/SQLite | 已有 Prisma Schema 12 模型，Sprint D 切 PostgreSQL |
| 数据库 | MongoDB + Redis | PostgreSQL + Redis | 关系型更匹配业务模型（权限、关联查询） |
| 缓存 | Redis | Redis | 保持一致 |
| 客户端 | React Native | Flutter 3.x | 已决策，三端统一 |
| 图片存储 | 阿里云 OSS | 腾讯云 COS / 阿里云 OSS（Sprint D 确定） | 二选一 |
| 推送 | 极光推送 | Flutter 本地通知 + Firebase Cloud Messaging | Flutter 生态适配 |
