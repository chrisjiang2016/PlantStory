## 二、今天完成的 H5 MVP 优化（开发 Agent 需知）

以下修改已直接写入代码文件，**开发 Agent 无需重复修改**，但需要理解逻辑以便正式开发时复用。

### 2.1 错误处理体系

**后端 `plantService.js` 三个核心函数全部改为：**
- `response.text()` → 手动 `JSON.parse`（try/catch）
- 输出结构化错误码，如 `BAIDU_TOKEN_FAILED`、`INVALID_API_KEY`、`IMAGE_BLUR`、`NO_RESULT`
- 不再依赖 `safeJson()` 包装函数

**前端 `app.js` 新增 `normalizeError()`：**
- 将后端错误码映射为中文用户提示
- 网络异常、JSON 解析异常均有降级提示

### 2.2 图片压缩流程

**`compressImage(file, maxWidth=1500, quality=0.85)`：**
- 使用 Canvas + `toBlob('image/jpeg')` 压缩
- 返回 `{ dataUrl, sizeKB }`
- 正式开发时建议将此逻辑移入独立工具模块

### 2.3 植物图片优先级

**优先级链路：**
1. `baike_info.image_url`（百度识花百科图片）→ 优先
2. `default_image.regular_url`（Perenual 植物详情图片）
3. 用户上传的识别照片（前端保存的 `imageBase64`）

**后端改动：** 百度识花请求参数增加 `baike_num: 5`

### 3.4 百度识花 API 注意事项

- **请求上限：** 单次 base64 编码后图片不超过 **4MB**
- **百度 Token 有效期：** 30 天（需定期刷新，建议服务端缓存 + 过期自动重取）
- **请求参数：** 需带上 `baike_num=5` 以获取百科图片
- **返回图片字段：** `result[0].baike_info.image_url`

### 3.5 Perenual API 注意事项

- **免费额度：** 300 次/天（建议服务端做本地缓存，存入 `plant_species` 表）
- **物种列表：** `/api/v2/species-list`
- **物种详情：** `/api/v2/species/details/:id`
- **详情中的图片字段：** `default_image.regular_url`
